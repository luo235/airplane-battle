# Airplane Battle

## 项目简介

Airplane Battle 是一个基于 Python + Pygame 开发的手机端适配飞机大战游戏。项目主要在手机 PythonIDE 环境中开发和测试，并针对移动端加入了全屏显示、屏幕比例适配、虚拟摇杆、触控移动和按钮百分比布局等设计。

游戏包含自动射击、敌机生成、随机升级、Boss 战、扇形弹幕、激光预警、移动模式切换、失败/胜利状态和数值成长系统等功能。

## 主要功能

- 手机端全屏适配
- 基于屏幕比例的 UI 布局
- 虚拟摇杆移动
- 触控移动模式
- 玩家自动射击
- 普通敌机与敌机子弹
- 玩家血条和经验条
- 随机升级技能
- 高级技能系统
- Boss 战
- Boss 扇形弹幕
- Boss 激光预警
- 游戏暂停、失败、胜利和介绍界面
- 爆炸动画和音效系统

## 运行方式

先安装依赖：

    pip install -r requirements.txt

进入 `src` 目录运行：

    python main.py

如果使用 PyCharm 运行，建议将 Working directory 设置为 `src` 目录，否则可能找不到 `resource` 里的图片和音效资源。

## 核心设计

### 状态机

项目使用状态机管理不同游戏流程。所有状态类都继承自 `BaseState`，并统一包含 `enter()`、`exit()`、`handle_events()`、`update()` 和 `render()` 五个基本流程。

菜单、游戏、暂停、升级选择、失败、胜利和介绍界面都被拆分成不同状态类，避免把所有逻辑都堆在主循环中。

### GameContext

`GameContext` 是游戏中的全局上下文对象，用来保存屏幕、配置、玩家飞机、敌机组、子弹组、Boss、按钮、HUD、动画列表和当前状态等对象。

不同模块可以通过 `game_ctx` 访问需要的公共数据，减少模块之间互相导入造成的混乱。

### Settings 数值配置

一开始我其实没有太把 Settings 类放在眼里，觉得只是放几个颜色、速度、血量之类的普通参数。但项目越写越大以后，我发现很多问题都和数值分散有关：比如重置游戏时有些属性没恢复，改难度时要到不同文件里找。

后来我把玩家子弹、飞机属性、敌机属性、成长数值、技能数值和 Boss 数值都逐渐整理进 Settings 类里，才发现这个类其实很重要。它让游戏数值变得集中、清楚，也方便后续调平衡和维护。这个过程让我意识到，写游戏不只是把功能做出来，后期维护和数值管理同样重要。

### 移动端适配

项目主要面向手机端运行，因此使用 `ScreenAdapter` 将屏幕百分比转换为实际像素坐标，使按钮、摇杆和文字位置能够根据屏幕大小自动调整。

移动方式上，游戏提供了虚拟摇杆模式和触控移动模式，玩家可以在主菜单中切换。虚拟摇杆使用半透明 Surface 绘制，避免遮挡飞机和战斗画面。

### 技能系统

玩家升级后会进入技能选择界面，系统会随机生成三个技能选项。每个技能选项由按钮和对应函数组成，玩家点击按钮后，会调用对应技能函数。

技能包括移速提升、子弹伤害提升、血量提升、攻速提升、回血、防御、削弱敌方子弹、副弹、吸血、碰撞伤害减免等。

### Boss 战

Boss 会在玩家生存到指定时间后出现。Boss 出现后会清空普通敌人，并进入 Boss 战阶段。

Boss 拥有普通子弹、扇形弹幕、激光预警、碰撞检测和血条显示等机制。激光技能会先显示预警区域，短暂延迟后进入真正伤害阶段，玩家需要及时躲避。

## 开发反思

这个项目让我认识到，写游戏不只是把功能做出来，还需要考虑代码结构、数值管理、状态重置和后期维护。

随着功能不断增加，`reset_game()` 也变得越来越重要。重新开始游戏不只是清空分数，还要重置飞机状态、敌人、子弹、Boss、动画、技能、冷却器和统计数据。

项目后期我也尝试过使用遗传算法进行自动调参，但后来发现自动测试 AI 不够接近真实玩家，尤其不会很好地躲避 Boss 激光和复杂弹幕。因此遗传算法更适合作为实验性尝试，最终游戏平衡仍然需要结合人工试玩调整。
